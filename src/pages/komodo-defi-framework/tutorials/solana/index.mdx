# Solana and SPL Tokens

The Komodo DeFi Framework supports Solana (SOL) and SPL tokens from both the Token and Token-2022 programs. Solana coins can be activated, hold balances, send transfers with memos, keep a transaction history, stream balance and history updates, sign messages, and take part in [atomic swaps](/komodo-defi-framework/tutorials/solana/#atomic-swaps).

<Note>
  Atomic swaps are implemented but **not enabled yet**: for now, Solana coins are wallet-only. Order methods such as [setprice](/komodo-defi-framework/api/legacy/setprice/) refuse them with `'SOL' is a wallet only asset and can't be used in orders.`, whatever the coins file says. Swaps will be enabled once the [satomic-swap](https://github.com/GLEECBTC/satomic-swap) program they use is audited and deployed to mainnet. The [Atomic swaps](/komodo-defi-framework/tutorials/solana/#atomic-swaps) section describes how they will work, so wallets can prepare for them.
</Note>

## Coins file entries

Solana coins are configured in the [coins file](/komodo-defi-framework/tutorials/coins-file-update/) like any other coin. The platform coin uses the `SOLANA` protocol, and each token uses `SOLANATOKEN`:

```json
[
  {
    "coin": "SOL",
    "name": "solana",
    "fname": "Solana",
    "mm2": 1,
    "wallet_only": true,
    "decimals": 9,
    "avg_blocktime": 0.4,
    "required_confirmations": 1,
    "derivation_path": "m/44'/501'",
    "protocol": {
      "type": "SOLANA",
      "protocol_data": {}
    }
  },
  {
    "coin": "USDC-SOL",
    "name": "usdc_sol",
    "fname": "USD Coin",
    "mm2": 1,
    "wallet_only": true,
    "avg_blocktime": 0.4,
    "required_confirmations": 1,
    "derivation_path": "m/44'/501'",
    "protocol": {
      "type": "SOLANATOKEN",
      "protocol_data": {
        "platform": "SOL",
        "decimals": 6,
        "mint_address": "EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v",
        "program_id": "TokenkegQfeZyiNwAJbNbGKPFXCWuBvf9Ss623VQ5DA"
      }
    }
  }
]
```

The `protocol_data` of a `SOLANATOKEN` entry takes the following fields:

| Parameter     | Type    | Description                                                                                                                                                                 |
| ------------- | ------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| platform      | string  | Ticker of the Solana platform coin the token lives on, e.g. `SOL`.                                                                                                          |
| decimals      | integer | The token's decimals, as set on its mint. The framework reads a token's decimals from here.                                                                                 |
| mint\_address | string  | Address of the token's mint.                                                                                                                                                |
| program\_id   | string  | The token program that owns the mint: `TokenkegQfeZyiNwAJbNbGKPFXCWuBvf9Ss623VQ5DA` for the Token program, or `TokenzQdBNbLqP5VEhdkAS6EPFLC1PHnBqCXEpPxuEb` for Token-2022. |

Activation fails if the mint exists but is owned by a different program than `program_id`.

For devnet, use the same entries with devnet tickers, `"is_testnet": true` and devnet mints. Devnet USDC, for example, is `4zMMC9srt5Ri5X14GAgXhaHii3GnPAEERYPJgZJDncDU` under the Token program. Devnet SOL is available from the [Solana faucet](https://faucet.solana.com) and devnet USDC from the [Circle faucet](https://faucet.circle.com).

## Activation

Activate SOL and any tokens with [experimental::enable\_solana\_with\_assets](/komodo-defi-framework/api/v20/coin_activation/enable_solana_with_assets/). To add a token later, use [experimental::enable\_solana\_token](/komodo-defi-framework/api/v20/coin_activation/enable_solana_token/).

Nodes are Solana JSON-RPC endpoints. A few things to keep in mind when choosing them:

*   **Transaction history comes from the node.** History and swap recovery read `getSignaturesForAddress`, so how far back they reach depends on how much history the node keeps.
*   **Public endpoints are heavily rate-limited.** `api.mainnet-beta.solana.com` and `api.devnet.solana.com` limit requests per IP, and fetching transactions in particular. They work for trying things out, but a wallet with `tx_history` enabled should use a dedicated RPC provider.
*   **Several nodes can be listed.** The first reachable node is used, and the next one is tried when it stops responding.

Solana activation supports wallets started from a seed phrase, in both Iguana and HD mode. Hardware wallets, WalletConnect and MetaMask are not supported.

## Keys and addresses

*   **HD wallets** (`"enable_hd": true`) derive the Solana key at `m/44'/501'/0'/0'`, the default path of Phantom, Solflare and `solana-keygen`. The same mnemonic gives the same address in those wallets.
*   **Iguana wallets** use the 32-byte private key the framework derives from the passphrase as the ed25519 seed. The address differs from what other Solana wallets derive from the same words.
*   **One address per wallet.** HD account and address selectors, such as the `address` parameter of [sign\_message](/komodo-defi-framework/api/v20/utils/message_signing/sign_message/), are not supported.
*   **Exporting the key.** [show\_priv\_key](/komodo-defi-framework/api/legacy/show_priv_key/) returns the base58-encoded 64-byte keypair that Phantom and Solflare import as a private key. [get\_private\_keys](/komodo-defi-framework/api/v20/wallet/get_private_keys/) does not support Solana yet.

### Token addresses

An SPL token reports the wallet's address, the same as SOL, in activation and [my\_balance](/komodo-defi-framework/api/legacy/my_balance/). The tokens themselves are held in the wallet's **associated token account** for the token's mint, an address derived from the wallet's. Senders' wallets and exchanges work it out from the wallet address, and create it if it doesn't exist yet.

When [withdraw](/komodo-defi-framework/api/v20/wallet/tx/withdraw/) is given a token account as `to`, as explorers often show, the tokens go straight into that account. A token account for a different mint, or any other account owned by a token program such as a mint, is refused with `InvalidAddress`.

## Fees and rent

### Network fees

A Solana transaction pays a base fee per signature plus a priority fee, which is a price per compute unit requested. The framework sets both parts of that priority fee:

1.  **Compute units.** It requests what the transaction needs plus 10%: a fixed amount for a SOL transfer, and an amount measured by simulating the transaction for a token transfer.
2.  **Price per unit.** It looks at the lowest price that transactions writing the same accounts paid in each of the last \~150 slots, and takes the 75th percentile, kept between 1,000 and 10,000,000 micro-lamports per unit.

Manual fees aren't supported: the `fee` parameter of [withdraw](/komodo-defi-framework/api/v20/wallet/tx/withdraw/) is ignored for Solana coins. The cost is reported in a `Solana` type [WithdrawFee](/komodo-defi-framework/api/common_structures/wallet/#withdraw-fee) object, and is always paid in SOL, token transfers included.

### Rent

Every Solana account must end a transaction either empty or holding at least its **rent-exempt minimum**: 0.00065024 SOL for a wallet at the time of writing. The framework checks this before signing a withdrawal, so a transfer that the network would reject fails with an error that says what would work instead:

| Situation                                                                        | Error                                                                                                                            |
| -------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| Sending SOL to an address that holds none, below the minimum                     | `AmountTooLow`, with the minimum as `threshold`. A smaller amount can still be sent to an address that already holds SOL.        |
| A SOL transfer that would leave the wallet with less than the minimum, but not 0 | `NotSufficientBalance`. Send less, so that the minimum stays behind, or send everything with `"max": true`.                      |
| An SPL token transfer the SOL balance can't pay for                              | `NotSufficientPlatformBalanceForFee`. The SOL balance must cover the fee and any rent, and keep the minimum unless it reaches 0. |

When the recipient of an SPL token transfer has no account for the token yet, the transaction creates one and the sender pays its rent. This is reported as `rent_amount` in the fee details, and stays in the new account rather than being burned.

`"max": true` on SOL sends the whole balance less the fee, leaving the wallet at exactly 0.

## Memos

[withdraw](/komodo-defi-framework/api/v20/wallet/tx/withdraw/) accepts a `memo` of up to 256 bytes for SOL and SPL tokens. It is recorded with the SPL Memo program, which exchanges and explorers recognize, so it can carry an exchange deposit tag. An empty memo is dropped, and a longer one fails with `InvalidMemo`.

## Transaction history

Activate with `"tx_history": true` and read the history with [my\_tx\_history (v2)](/komodo-defi-framework/api/v20/wallet/tx/my_tx_history/); the legacy `my_tx_history` doesn't support Solana. The history covers SOL and every token activated with it:

*   Amounts are worked out from balance changes, so transfers made by any program are recorded, not only plain transfers.
*   A token transfer appears as a row for the token. When the wallet paid for it, it also appears as a row for SOL, for the fee and any rent.
*   History is fetched oldest first. The newest transactions appear once the sync reaches them, and new transactions are picked up every 30 seconds.

[stream::tx\_history::enable](/komodo-defi-framework/api/v20/streaming/tx_history_enable/) streams new history entries for SOL and for each token.

## Balance streaming

Enable [stream::balance::enable](/komodo-defi-framework/api/v20/streaming/balance_enable/) on the platform coin only. That one stream reports the balances of SOL and of every token activated with it. Balances are polled every 10 seconds, so an update can take that long to arrive.

## Message signing

[sign\_message](/komodo-defi-framework/api/v20/utils/message_signing/sign_message/) produces an ed25519 signature over the raw UTF-8 bytes of the message, encoded in base58. This is the scheme Phantom and Solflare use for `signMessage`, so signatures verify in either direction. No `sign_message_prefix` is needed in the coins file.

## Atomic swaps

Solana swaps use the same methods as any other coin: [setprice](/komodo-defi-framework/api/legacy/setprice/), [buy](/komodo-defi-framework/api/legacy/buy/) and [sell](/komodo-defi-framework/api/legacy/sell/) to trade, [trade\_preimage](/komodo-defi-framework/api/v20/swaps_and_orders/trade_preimage/) and [max\_taker\_vol](/komodo-defi-framework/api/legacy/max_taker_vol/) to plan a trade, and [my\_swap\_status](/komodo-defi-framework/api/legacy/my_swap_status/) and [my\_recent\_swaps](/komodo-defi-framework/api/legacy/my_recent_swaps/) to follow it. This section covers what differs for Solana.

### How a Solana swap works

*   **The payment is held by a program.** Each side of a swap locks its payment with the [satomic-swap](https://github.com/GLEECBTC/satomic-swap) HTLC program: `54mDjQz6jS9sggCV1P5GoUzqHaBEueGVZqmaMPLt2tDx`, live on devnet and not yet deployed to mainnet.
*   **The payment's address is derived from its terms**: the sender, the receiver, the secret hash, the lock time and the amount, plus the mint for a token. The account at that address holds the SOL, or owns a vault holding the tokens. It is closed when the payment is spent or refunded, and its rent goes back to whoever paid it.
*   **The receiver can spend the payment at any time** by revealing the secret. **The sender can refund it once the lock time has passed**, judged by the cluster's clock rather than the local one.
*   **Only the two parties can act on a payment**, so Solana swaps don't support watchers. Keep the node running until a swap finishes or is refunded.
*   **Solana swaps use the legacy swap protocol**, also when [`use_trading_proto_v2`](/komodo-defi-framework/setup/configure-mm2-json/) is enabled, with SHA-256 secret hashes. Solana coins can swap with any coin that supports legacy swaps. They have been tested against UTXO coins.
*   **Token-2022 mints that charge a transfer fee can't be swapped**, nor can those whose transfer fee is zero but could be raised later. The program refuses such a payment before any funds move, because the receiver would get less than the swap promised.

### Orderbook

A Solana maker's address can't be worked out from an order, so the v2 [orderbook](/komodo-defi-framework/api/v20/swaps_and_orders/orderbook/) and [best\_orders](/komodo-defi-framework/api/v20/swaps_and_orders/best_orders/) report it as `{"address_type": "Shielded"}`, as they do for ARRR. The legacy methods can't show Solana orders: the legacy [orderbook](/komodo-defi-framework/api/legacy/orderbook/) fails for a pair with a Solana order on it, and the legacy [best\_orders](/komodo-defi-framework/api/legacy/best_orders/) leaves them out. Use the v2 methods.

### Swap fees

Every Solana transaction fee in a swap is paid in **SOL**, also when the coin swapped is an SPL token. A wallet swapping a token needs SOL as well, as an ERC20 swap needs ETH.

[trade\_preimage](/komodo-defi-framework/api/v20/swaps_and_orders/trade_preimage/) and [max\_taker\_vol](/komodo-defi-framework/api/legacy/max_taker_vol/) report **upper bounds**, so a swap never starts without enough SOL to finish:

*   Each transaction is priced at the highest priority fee the framework ever pays, for the most compute it can use.
*   The rent the payment locks up is included. It comes back when the payment is spent or refunded, but has to be in the wallet when the payment is made.
*   Token swaps also include the rent for opening a token account, wherever one may need opening.
*   The wallet's own rent-exempt minimum is included, because the network refuses a transaction that leaves the wallet below it.

A swap usually costs far less than its estimate. Show these figures as the most a swap can cost rather than what it will cost.

For example, a `trade_preimage` for selling 2 USDC on devnet for DOC. The token's dex fee (`taker_fee`) is paid in USDC, and every network fee on the Solana side in SOL:

```json
{
  "userpass": "RPC_UserP@SSW0RD",
  "mmrpc": "2.0",
  "method": "trade_preimage",
  "params": {
    "base": "USDC-SOL-DEV",
    "rel": "DOC",
    "swap_method": "sell",
    "price": "1",
    "volume": "2"
  },
  "id": 0
}
```

### Confirmations

Solana finality is a commitment level rather than a number of blocks, so `required_confirmations` (from the coins file, or `base_confs` and `rel_confs` on an order) is read as:

*   `0`: wait until the transaction is `confirmed`, which means a supermajority of the cluster has voted on it. This usually takes a second or two.
*   `1` or more: wait until it is `finalized`, about 13 seconds after it lands.

`requires_notarization` has no effect on Solana coins.

### Following and recovering a swap

*   Swap events in [my\_swap\_status](/komodo-defi-framework/api/legacy/my_swap_status/) are the same as for any legacy swap. A Solana `tx_hash` is the transaction's base58 signature. Open it at `https://explorer.solana.com/tx/<tx_hash>`, adding `?cluster=devnet` for devnet.
*   An interrupted swap resumes when the node restarts, and [recover\_funds\_of\_swap](/komodo-defi-framework/api/legacy/recover_funds_of_swap/) works as for other coins.
*   Because a settled payment's account is closed, both find a payment through the transaction history of its address. The node must keep history that reaches back to the start of the swap.

## Other methods

*   [validateaddress](/komodo-defi-framework/api/legacy/validateaddress/) accepts any base58-encoded 32-byte address.
*   [convertaddress](/komodo-defi-framework/api/legacy/convertaddress/) returns an error: Solana has a single address format.
*   [min\_trading\_vol](/komodo-defi-framework/api/legacy/min_trading_vol/) is one lamport, `0.000000001` SOL.
*   `sign_raw_transaction` is not implemented for Solana.
